# tea_shelf

使用 Scripting 开发的个人茶架应用，应用名为“茶管家”。

本文维护当前页面功能栈及基本数据约定。后续规划需单独标注，避免与已实现功能混淆。

版本号保存在 `script.json`，每次 push 前按北京时间更新为 `yyyyMMdd-HHmm`，随本次提交推送。

本文档Agent不要直接编辑，仅提供修改建议，或在我明确要求代写内容时进行编辑。

## 页面

### 首页

- 标题栏
  - 应用名。
  - 左侧应用版本号。
  - 右侧“新增茶品”按钮。
- 首页工具栏
  - 工具按钮
- 茶品列表
  - 茶品卡

### 首页工具栏

- 控制按钮高度40
- 当前使用普通横排，不单独滚动；按钮增多后的横滑为后续规划。

#### icloud

- 打开标题为“icloud存档”的只读列表页，每次进入时读取存档目录。
- 每行仅显示一个存档目录名，按日期倒序排列。
- 过滤临时目录、非存档目录及普通文件。
- 支持加载、无存档、iCloud 不可用及原始错误提示。
- 暂时不追加操作

#### 配置

打开配置页，当前可配置项：
- 首页工具按钮图标字号：默认30
- 首页工具按钮文字字号：默认10
- 首页工具按钮向上偏移：默认0

保存在meta.config中

### 茶品卡

- 每行两张卡片，最小高度 109；长文本可撑高，并非固定高度。
- 依次展示品名、品牌、底部信息行。
  - 底部信息行展示个人偏好、存量和斤价。
- 点击进入编辑，删除需要在编辑页进行

### 茶品编辑页（新建共享）

- 右上角“保存”写入本地并返回列表；
- 品名必填，输入控件右对齐。
- 品牌必填，一行为“标签 + 下拉框 + 加号”，下拉与加号间距 12
  - 加号弹窗新增品牌，确认后立即保存到品牌列表并选中。名称去除首尾空白，拒绝空名称和重复名称；即使之后放弃茶品编辑，已新增的品牌仍保留。
- 现有茶品的编辑页底部显示独占一行的红色“删除茶品”按钮，确认后删除并返回列表；新增页没有删除按钮。
- 表单字段不一一列出

## 样式

### 配色

首页背景、导航栏背景、工具栏按钮及茶品卡片的绿色系配色统一在 [core/theme.ts](core/theme.ts) 定义，随系统深浅模式自动切换。卡片为纯色背景，按钮图文为白色。

## 数据

### meta.json

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 元数据结构版本，目前为 1 |
| `updatedAt` | 本地数据最近更新时间，UTC 时间字符串，初始为 `null` |
| `lastSyncAt` | 最近成功备份的数据版本时间，取备份快照的 `updatedAt`，初始为 `null`；并非备份执行结束或云端上传完成时间 |
| `files` | 有效数据文件清单，如 `["data.0.json"]` |
| `brands` | 品牌名称字符串列表，没有独立品牌管理页 |

### data.0.json

目前保存 `{ "schemaVersion": 1, "teas": [...] }`，尚未实现分块切分。每个茶品包含：

- `id`：稳定标识，编辑和删除按此定位。
- `name`、`brand`...：品名、品牌名称、个人偏好、斤价、存量。
- 品牌存名称字符串，不是关联 ID。
- 个人偏好存字符串不是关联ID。
- 泡法字段等不一一列出

### 本地与备份

- 日常读写本地数据目录；iCloud 用于备份，不提供多设备双向同步。
- 启动时及运行期间每 10 分钟检查未备份更新；保存只更新本地数据，不触发即时备份。
- iCloud 按设备本地日期生成 `tea_shelf.YYYY-MM-DD` 目录，同日覆盖，新备份成功后保留最近 5 个日期目录。
- iCloud 不可用不影响本地读写；首次初始化的空数据不自动备份，尚无云端恢复入口。
- 目录位置、失败处理和存储 API 详见 [core/storage/README.md](core/storage/README.md)。

## 从 GitHub 导入或更新

在 Scripting App 中导入脚本子目录地址，或在已有脚本的设置中配置远程来源，再手动检查更新。以下仅为路径示例，使用时替换为实际的完整地址：

`xxxx_project/tree/main/tea_shelf`

请使用脚本子目录地址。仓库根目录包含多个项目，不是本脚本的目录。

导入或更新完成后，运行 `tea_shelf`，页面直接显示茶品列表。如果仍显示示例内容，请先在脚本编辑器中确认项目文件已更新为本仓库的内容。

## 本地文件

- `script.json`：脚本名称、图标、版本等配置。
- `index.tsx`：主应用入口。
- `core/storage/`：本地文件存储与 iCloud 按日备份，详见该目录的 README。
- `pages/`：首页、首页工具栏、茶品列表、茶品编辑及 iCloud 存档列表。

手动导入时，应将配置、入口和 `core/`、`pages/` 目录一起放到 Scripting 的同一脚本目录中。

关闭页面后，脚本会调用 `Script.exit()` 释放资源。

参考：[Scripting 快速开始](https://scriptingapp.github.io/zh/guide/Quick%20Start)、[远程脚本来源与更新](https://scriptingapp.github.io/zh/guide/Script/Script#远程脚本来源与更新)。
